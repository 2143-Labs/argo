## 4. Phase 1 — `edge-tofu` skeleton (no credentials, no spend)

Deliverable: the repo the doc specifies, with everything stubbed except the parts that can be correct today.

```
versions.json          Talos v1.14.0 + schematic id; tofu + provider pins; placeholder image digests
images/                Dockerfile stubs for derper, tinyproxy, edge-connector + mirror list
talos/                 machine-config templates: firewall, wireguard, static pods (from doc §6)
edge.yaml              turn/derp service definitions (from doc §8)
manifest.lock          empty; schema documented
tofu/modules/edge/     provider-agnostic VM module (variables: slot, provider, size, user-data)
tofu/providers/        hcloud/, digitalocean/ skeleton modules; no resources created by CI
bin/edge.py            render | verify | plan | roll | rotate-slot | drill — render implemented first
deployments/           .gitkeep + record schema
.github/workflows/     pr.yml (render fixtures + tofu validate + shellcheck), release.yml stub
```

**Acceptance for Phase 1**
1. `bin/edge.py render --manifest fixtures/home.yaml --slot s1` emits a Talos machine config that parses and contains the declared ports.
2. `tofu validate` passes in both provider modules (no `apply` in CI).
3. `pr.yml` runs render + validate + shellcheck and fails on a duplicate-ownership fixture.
4. No cluster, provider, or DNS state is touched.

**Explicitly out of scope for Phase 1:** building/signing images (needs registry + cosign identity), OpenBao integration, and any `tofu apply`.

## 6. Consequences of the separation (D24)

- **A second ARC scale set is required.** The existing `edge-deploy` plan assumed a scale set registered to `2143-Labs`. A repo in a new organisation needs its own runner scale set, which means a GitHub App installed on that organisation — a separate credential from the current one.
- **Signing identity changes** to `https://github.com/<new-org>/edge-tofu/...`; the cosign verification policy must pin that, not the 2143-Labs identity.
- **DigitalOcean moves to a new business account.** That gives a fresh transfer pool (no Tor relay), a separate API token and a business invoice; the personal account keeps DOKS, `status-1` and the relay untouched. Accounts and teams are free — the only cost is the Droplet itself. New accounts need a payment method and may start with lower resource limits until verified; confirm region/size availability before Phase 3.
- **Hetzner is a new business account** under `labs@2143.me`: separate billing and token, nothing shared. Confirm ASH1 stock and the current CPX11 price on that account before locking the module.
- **DNS is unaffected:** the controller and its deSEC token stay at home, so the edge accounts still cannot repoint a name.
- **Billing splits along the business/personal line**, which is what an LLC wants: edge spend on the business, home and DOKS on the personal account.
