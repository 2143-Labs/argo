The WireGuard path

One tunnel, one peer. The router terminates wg-remote on 10.99.0.1/24 (UDP 51820, WAN input rule); the DigitalOcean cluster dials john2143.com:51820 and holds 10.99.0.2/24. Its wg0 carries both LAN subnets, so every VIP and every node IP is routable from that cluster — reachability is limited by what runs there, not by routing. The router does not masquerade the tunnel into the LAN.

That is a full LAN route, not a pair of holes. allowed-ips on the DO side is 10.99.0.0/24, 192.168.5.0/24, 192.168.6.0/24 and the router forwards without NAT, so any pod on that cluster can address any home VIP or node directly. Only haproxy’s two backends and DNS do. Narrowing the peer to 10.99.0.0/24 plus two /32s would make the intent explicit; nothing depends on the wider range today except mongo’s return path, which needs 10.244.0.0/16.

What this shows

Seven VIPs are single-node. .6.6 traefik announces from closet and arch (three replicas), so the public edge survives losing either one. .6.13 stalwart is nas-only, .6.15/.6.16/.6.29 are closet-only, and .6.18/.6.28 are arch-only. Lose that node and the VIP is withdrawn — for the games, that is the session.

Ten VIPs face the internet, ten do not. The other ten are LAN, tailnet or WireGuard only — including all of observability (.6.23–.6.25), .6.31 seaweedfs, .6.30 DNS and .5.10 the API. Nothing in that group has an inbound rule, which is the point.

Failure is closed by default. 192.168.6.0/24 sits in the routing table as an immediate-gw=blackhole distance=250 route. An unannounced VIP drops; it never falls through to the LAN default route. That is why .6.17 and .6.26 simply time out today instead of answering from the wrong place.

The selected path is lopsided. With ECMP off, the router prefers closet for 17 of the 19 routed VIPs. That is a routing-table artifact, not a load-balancing policy — arch and nas carry traffic only for what they uniquely announce. If that ever matters, the fix is moving .6.x services to Local, not re-enabling multipath.

How to re-check

# VIPs, ports, announcement policy, node ports
kubectl get svc -A -o json
kubectl -n kube-system get pods -l app.kubernetes.io/name=traefik -o wide

# which node carries each prefix (selected path), and the WAN forwards
mikrotik-connect r '/ip route print terse where dst-address~"192.168.6." and active=yes'
mikrotik-connect r '/ip firewall nat print terse where chain=dstnat'

# listener set on a node
ssh 192.168.5.36 'sudo -n ss -ltnuH | awk "{print \$1, \$5}" | sort -u'

# WireGuard: both ends, then the live flows
mikrotik-connect r '/interface wireguard peers print detail'
kubectl --context 2143prod -n default get deploy wireguard-doks -o yaml
kubectl --context 2143prod -n default get cm home-tunnel-proxy -o yaml
mikrotik-connect r '/ip firewall connection print terse where src-address~"10.99" or dst-address~"10.99"'
